# Changelog

## Unreleased, target 2.1.0

This section describes the current source tree. It does not claim that `2.1.0` has a Git tag or GitHub Release.

### Gate authoring

- Add `scripts/gate-lint.mjs`, a non-executing advisory audit of ledger quality. Warn on whole fixed-output commands, weak success vocabulary, shared-parser path ambiguity, activity titles, unmeasured manual numbers, and mostly manual ledgers without pretending to shell-parse chains or argv. Default warnings retain a `LINT OK` marker and exit `0`; `--strict` makes them fail. Reject unknown short and long options.

### Correctness and fail-closed behavior

- Replace positional-argument index arithmetic with a validating CLI parser. An explicitly named ledger is the only ledger targeted, regardless of option order.
- Use one strict ledger parser for the checker and Stop hook. Reject zero-gate ledgers, duplicate ids, partial runnable gates, invalid regular expressions, blank abandonment reasons, unknown abandonment ids, and unindented attributes. Validate CLI options and scope ids separately, and reject invalid `OWNS:` paths when claiming a lease.
- Ignore fenced examples, preserve CRLF or LF during updates, and insert a missing evidence line into an otherwise valid gate.
- Match CommonMark fence length, marker, indentation, and closing-line rules so nested shorter fences cannot expose example gates.
- Add `--reverify` so parent verification executes already checked runnable gates and removes completion when the oracle no longer passes.
- Require both process exit `0` and `EXPECT:` match. Include resolved shell, resolved working directory, exit status, match state, and a SHA-256/byte-count output fingerprint in persisted evidence; keep bounded raw diagnostics terminal-only on failure.
- Discard an in-flight result when the gate's bound oracle changes before writeback.
- Diagnose an indented `ABANDON:` instead of ignoring it. Attributes must be indented and `ABANDON:` must not be, so the natural formatting mistake previously left a gate unmet and the honest exit unexplained.
- Warn when a slash-wrapped `EXPECT:` containing an unescaped inner slash is read as a regular expression. A literal path silently became a pattern whose dots matched any character, and the wrapping slashes leave no way to express the literal.
- Treat gate abandonment as terminal handoff rather than successful completion. Checker modes now exit `1` with `HANDOFF REQUIRED`, parent `ALL MET` promotion cannot accept an abandoned child, and Stop allows exit with a bounded qualified-id message.
- Include scoped dispatch state in the primary gate reduction, so open, sealed, or abandoned waves can never coexist with `ALL MET`. Reject fabricated terminal histories, non-string handles/reasons, missing lifecycle timestamps, and impossible timestamp order.
- Sanitize repository-controlled dispatch diagnostics before they reach a host hook message, retain qualified abandonment handoffs in mixed block/release outcomes, and discard malformed per-session hook entries instead of failing open.
- Refuse status-log symlinks and swapped/non-regular targets before appending, including automatic dispatch audit events.
- Strip terminal controls and bidirectional overrides from repository-controlled checker diagnostics.
- Separate regular-expression worker startup from the 250ms match budget and cap concurrent match workers at four, so high `--jobs` values remain fail-closed without startup-induced false failures.

### Command trust and portability

- Add explicit `--approve` execution consent for ledger commands. Store approvals under `~/.unlazy/approved` by default, require the canonical owner-private store to remain outside the repository, reject linked/replaced/non-private records, and bind each approval to the absolute ledger and gate, command, expectation, resolved working directory and shell, timeout, output and regex limits, regex worker limits, platform, and inherited `PATH`.
- Add `--shell` with `UNLAZY_SHELL` fallback. Keep the platform shell as the final default and make inherited `PATH` behavior visible.
- Replace POSIX-only gate examples with repository-owned Node scripts and document Windows shell and PATH variance.
- On Windows timeouts, terminate an active `cmd.exe` tree with the drive-root `<drive>:\Windows\System32\taskkill.exe` only when `SystemRoot`, `WINDIR`, and `SystemDrive` agree. Bound the helper itself to one second, inspect every result, and fall back to the direct child without PATH lookup. Skip numeric-PID cleanup when Node has already observed leader exit, and independently settle after cleanup even when descendants retain pipes. The Windows CI path launches and reaps a real shell plus nested Node descendant.
- Keep a detached Node supervisor alive until each shell and inherited output stream closes. POSIX cleanup signals the group only while that exact supervisor still owns its PID/PGID, preventing a reused numeric group from being targeted without regressing descendant cleanup.
- Add [SECURITY.md](SECURITY.md) for command, environment, installer, hook, evidence, scope, and lease boundaries.
- Clarify that approval binds declared oracle text/environment, not called scripts or other transitive files, while `--status` and Stop report historical evidence until explicit `--reverify`.

### Orchestration and concurrency

- Enforce declared dependencies. `open` refuses a wave naming a leaf whose `Needs` are unsatisfied and exits `3`. `PLAN.md` carried a `Needs` field and a five-state vocabulary that nothing read: no script parsed the plan at all, so a leaf explicitly marked `WAITING` on an unverified dependency opened a wave cleanly. Satisfaction is read from the dependency's own ledger through the shared `ledgerCompletion` reduction, and compared against the plan's `State` field, so a ledger complete while the tree still calls it `WAITING` is a refusal that names the mismatch rather than a claim taken on trust. A scope with no `PLAN.md` is not dependency checked, since a plan is only required once work is split.
- Lint `PLAN.md`. Parsability belongs to the planning stage: a tree that cannot be read means planning did not finish, so `gate-lint.mjs` now lints a plan, `open` refuses while an unreadable one stands, and a scope holding one cannot reduce to `ALL MET`. Unknown dependency ids, cycles, duplicate ids, a state outside the vocabulary, and a row whose ledger names a different id are errors; a state inconsistent with its own dependencies is a warning.
- Add `scripts/lib/plan.mjs`, which reads the tree by extracting the tokens that carry meaning rather than parsing the layout, so decorative dot leaders stay irrelevant and a plan remains readable to a human without becoming a fragile format. Parsing is confined to the `## Tree` section, because a reader loose enough to take ordinary prose bullets would invent dependencies out of sentences.
- Audit ownership against version control on reverification. Registration pins the repository's current commit, and `--reverify` compares the leaf's real changes against it. Every other record here is written by the agent, or by a tool the agent chose to run, so it states an intention; history states what happened, and is the only evidence the checked leaf did not author. Paths registered to another leaf leave the leaf unverified when the comparison describes that leaf alone, paths nobody holds warn, and an audit that cannot run leaves the leaf unverified with the reason recorded rather than silently passing. Committed, uncommitted, and untracked changes all count, both sides of a rename count, created files are covered by the declaration rather than exempt from it, and `.unlazy/` is excluded. Nothing is reverted: an unverified leaf keeps its work and owes a decision. This is unlazy's first use of git, kept to a read-only two-question surface in `scripts/lib/git.mjs`.
- Add `pathMatchesGlob`, an exact path-against-declaration matcher, rather than reusing `globsOverlap`. That comparison answers a different question between two declarations and is biased to report a conflict whenever it cannot be sure, which is a harmless nudge there and a false accusation against finished work here. A pattern the matcher does not decide reads leniently and never becomes a finding.
- Enforce participation in the ownership protocol. `dispatch-check.mjs open` now refuses a wave naming any leaf that holds no registration for its scope and exits `3`, matching `gate-check`'s lease-conflict code. The docs said "claim every leaf first" and nothing checked it, so skipping registration was strictly cheaper than performing it: fewer calls, and it could never refuse. `open` answers the question from lease records the checker itself wrote, so it reads no ledger and a leaf cannot omit anything from its own paperwork to escape the requirement. Refusal sits at `open` rather than `seal` because by seal the leaves have already launched and already written, so a check there reports a collision instead of preventing one. Malformed scope and leaf ids are still reported as shape errors with exit `2`, so a traversal id cannot surface as a missing registration.
- Let a leaf that declares no `OWNS:` paths register. Refusing a pathless claim left such a leaf unregisterable, which made omitting the `OWNS:` line a way out of the protocol rather than the strictest position inside it. A pathless registration records that an identity exists and may change nothing.
- Verify an isolation claim at `start` instead of trusting it. `dispatch-check.mjs start` accepts `--workspace <path>` and refuses, exit `3`, a path that does not exist, a main checkout, or an exclusive worktree of a different repository, that last being the exact shape a misdirected launch-tool isolation produces: a real worktree of the wrong tree, passing every test except whose history it advances. One wave watched a leaf's isolation fall through silently and commit straight onto the shared checkout, caught only by the driver auditing git afterwards. The flag is opt-in and never soft, because an unverifiable isolation claim recorded as fact is the false paperwork this tool exists to keep out; a `start` that claims nothing behaves as before. `exclusiveWorktree` now also reports the repository's common git directory so two trees can be compared.
- Print ownership audit findings to stdout. The lines naming which files a warning was about went to stderr while the verdict stayed on stdout, so a stdout-only capture kept `ALL MET` and lost the only text saying what to go look at. Audit findings share the verdict's stream; tool diagnostics stay on stderr.
- State the remedy inside the `--scope`-with-explicit-file refusal. `--help` lists `--root` and `--cwd` but never connects them to this error, so two testers in one round were left knowing they were wrong with no stated way to be right.
- Point at the missing tick when a manual gate holds recorded evidence behind an unchecked box. `(unchecked)` beside a fully written `EVIDENCE:` line reads as a missing step somewhere else, and a tester re-walked the whole flow hunting for one. The box stays manual, because the tick is the reviewer's signature.
- Give `SKILL.md` copyable scoped forms beside its two solo examples, which fail by design in a scoped project a reader meets them from.
- Warn that a scope-wide `--reverify` from the main checkout while leaf branches are unmerged measures a tree the work does not exist in, and its failures are indistinguishable from a regression; treat "everything failed at once" as a which-tree question first.
- Spell out the worktree-to-merged-root approval direction: reverifying a merged child at the root `--cwd` is a third bound working directory needing its own reviewed approval, and a branch gate nesting `gate-check --reverify` cannot grant it itself. One approval per leaf per direction. The template comment in `gates-node.md` now says so beside the gate that fails without it.
- Lint a `VERIFIED` plan row against the ledger it claims. `VERIFIED` is the one state other machinery believes, because dispatch admits dependents on it, and it is written by hand: a tester hand-set it on a row whose ledger had never come clean and got `LINT OK` even under `--strict`, so the one completion claim worth auditing was the one nothing audited. The ledger sits on disk next to the plan, so the claim is checkable without executing anything. First shipped as a warning on the theory that mid-edit trees are legitimate; the first naive reader then reported the finding "buried inside an overall LINT OK, exit 0" and skimmable, so a `VERIFIED` row over a ledger that exists, parses, and is incomplete is now a lint error, exit `1`, because two on-disk records that certainly contradict is not a suspicion. A missing or unparseable ledger stays a warning, since there the claim is undecidable rather than false. Wave admission is untouched either way: `open` refuses on the plan's structural errors, so drift stops the lint gate without freezing unrelated dispatch. An honest `VERIFIED` row is still not questioned.
- Give `SKILL.md` the scoped `--approve` form beside its scoped `--status` examples, name the canonical ledger layout `.unlazy/<scope>/gates/leaf-<id>.md` in prose rather than only inside an example string, show the literal `gate-lint.mjs .unlazy/<scope>/PLAN.md` invocation at the point that commands linting, and say that `--approve` prints, records, and executes in one invocation, which its prose previously left readable as a two-step flow.
- State in `references/gates.md` that everything load-bearing in the checker's report goes to stdout and stderr carries only tool diagnostics; a tester proved it empirically across four scenarios and rightly asked why it had to be proven instead of read.
- State in `SKILL.md` how to target one leaf's ledger inside a scope: drop `--scope` and name the file with `--root` (and `--cwd` when executing). The headline examples do not compose with `--scope` as written, and the rule lived only in `references/dispatch.md`, so a reader following the top-level document combined them and got the mutual-exclusion refusal.
- Document how the two Stop-hook releases persist. The six-block release re-arms when the resolved state changes, because from the hook's seat a change is what progress looks like; the session ceiling is permanent once crossed. A tester reported the release as flatly permanent, which held in their run only because their session total was already past the ceiling; the distinction was measured before being written down here.
- Carry the ownership warning count into the verdict line, and say so when an audit comes back clean. The warning went to stderr above a summary that still read `ALL MET` and still exited `0`, so a reader watching that exact scrollback caught it while anyone reading the verdict, checking the exit status, or asking again five minutes later did not: it is never written to the ledger, never appears in `--status`, and is never appended to the status log. Two testers reported it independently, one noting the run "silently degrades from proved this leaf's provenance to proved nothing about provenance, said so on stderr, and reported ALL MET anyway". A clean audit now says so too, because printing nothing is indistinguishable in a transcript from an audit that never ran, and one tester built their own positive control before they would trust the silence.
- Correct the synchronous-launch sequence in `references/dispatch.md`. The guidance added one revision earlier told a host with no background launch to seal the wave before issuing its launches, which `seal` refuses outright because it requires a `start` record for every leaf: a tester followed it verbatim and got `cannot seal ready-1: missing starts for leaf-1.1.1, leaf-1.1.2`. The order the tool accepts is open, batch every launch into one message, record each `start` from the id its call returned, seal, then return. Batching is what preserves the barrier; sealing early is how a host that returns handles up front evidences that barrier, and is simply unavailable here.
- Bound Stop-hook blocking by a per-session ceiling as well as the consecutive one. The six-block progress guard is keyed to a hash of resolved gate and dispatch state, so any change to that state rearms it from zero, including a change that accomplishes nothing: renaming an unmet gate each round is not progress by any useful measure but does move the hash, and blocked eight times out of eight under test without ever releasing. A guard whose only release condition can be rearmed by the behaviour it exists to bound does not bound anything. Twenty-four blocks in one session now release it whatever the state did, the consecutive rule is kept because it releases a visibly stuck agent far sooner, and each block reports its distance from both ceilings so nobody has to read the state file to learn how close release is.
- Answer `--help` in `stop-hook.mjs`, naming the two stdin fields it reads, that it always exits `0` because the host reads the JSON body rather than the exit status, and that it executes no `CHECK` line. Every other script here answers `--help`; this one printed nothing, and three separate readers trying to exercise the hook had to source its input contract from outside the skill.
- Reverify worktree children per worktree in `templates/gates-node.md`. Its integration gate showed one shared `--cwd` naming every child, which is the wrong tree for all of them once each child worked in its own worktree, while `dispatch.md` said to reverify each against the tree it worked in. Two shipped documents pointed opposite ways, and a reader following the template got a finding about work none of the children did.
- Say `ownership was not audited` on a run that did not reverify. The approving run is the one that first turns a leaf green, so it is exactly where a trespass already committed goes unmentioned while `ALL MET` prints; a leaf that had already written into a sibling's registration was reported clean by it. An unregistered ledger is outside the protocol and is not nagged.
- Describe a host with no background launch in `dispatch.md`. Some Claude Code contexts expose only a synchronous `Agent`, where launching and waiting are one act and no handle exists to record before sealing, so the wave protocol cannot be satisfied literally. Three testers met this and each invented a different workaround, one of them recording a handle it had made up. Batching every launch into one message preserves the barrier the protocol exists to enforce; the handle ordering is evidence of that barrier, not the barrier itself.
- Capture the ownership change set before any oracle runs. The audit measured the tree after the checks had executed, so anything a check wrote while verifying, a compiler cache or a build artifact or a coverage file, landed in the leaf's own change set. A leaf that committed exactly one correct file was refused because its own approved check regenerated bytecode beside it, and the flagged paths were indistinguishable in the output from a real stray edit. Verifying something must not change what is being measured about it. A missing snapshot is reported as an audit that did not run rather than quietly re-measured, so the pollution cannot return by a fallback.
- Say `ALL MET ... from recorded evidence; nothing was executed and no ownership was audited` when `--status` reaches that result. `--status` reads stored checkboxes, executes no oracle and audits no ownership, and printed the identical sentence an executed run prints. After a merge, a rename, or a removed worktree that recorded evidence can describe a tree that no longer exists, and two testers independently reported nearly reporting a leaf verified on it. An executed run keeps the plain sentence, so the caveat continues to distinguish something.
- Name the rule in the plan-tree lint error: `tree row id must be digits and dots only, like 1.1.2, got "parser"`. The old `tree row has no leading id` reads as a spacing or formatting complaint, so a reader who had named a row for what it builds could not learn the character class from it and went looking through documentation for a rule the message could have stated.
- Note outstanding dependencies at `--claim`. Claiming reserves paths; it does not clear a leaf to run. A bare `CLAIMED` reads as permission to proceed, and the refusal only arrived later at a wave the reader had by then designed around. The note appears only where a wave would actually refuse.
- Explain which mode rejected an execution-only flag, and that `--root` survives it. The documented form for an explicit ledger carries `--root` and `--cwd`, so copying that shape into a `--status` call produced a refusal naming four flags without saying which mode objected or what to drop; three separate testers each spent a call discovering it.
- Name the resolved root when a wave is unknown. Scope state resolves from `--root`, which defaults to the invocation directory, so the ordinary cause is running from the wrong place. Naming only the wave sent one reader hunting for lost state and led them to conclude the command had no `--root` at all, which it has had on every subcommand throughout.
- Say that an empty repository needs one commit before a leaf can register. `Initialise a repository` was already satisfied by a reader who had run `git init`, and a repository with no `HEAD` reports the same missing starting commit that no repository does.
- Establish that the ownership comparison describes one leaf before accusing it of a collision. The comparison starts at the leaf's own pinned commit but ends at its working tree's `HEAD`, and only an exclusive tree makes "what changed here" the same question as "what did this leaf change". Where leaves shared one checkout, a sibling's own committed work landed inside every other leaf's range and matched that sibling's registration, so correctly registered, already verified work was refused as a trespass, in both directions, for pipelines that had done nothing wrong. Three independent testers and a blind control hit it. A finding raised where the tree is shared now warns and names what could not be decided; from a worktree of its own it still refuses, because there the range cannot contain anyone else's work. The requirement is one leaf per working tree rather than worktrees as such: a single leaf left in the main checkout while its siblings are isolated is decidable, and the previous docs' worktree rule covered only concurrently dispatched leaves while the audit bound every registered one.
- Refuse a wave naming a leaf the plan does not describe, instead of skipping its dependency check in silence. Satisfaction is read from the row whose ledger matches the leaf, so a ledger named for what it builds matched no row and the leaf's `Needs` were never looked up: identical work refused as `leaf-1.1.2.md` and opened cleanly as `leaf-cli.md`. Descriptive naming is an ordinary choice, so the enforcement was opt-out by accident while the pipeline still read as protected. A plan that does not describe the leaf being dispatched is unfinished planning, exactly like one that cannot be read.
- Report a met gate whose oracle is unapproved rather than passing over it. A gate already recorded as met is not re-executed outside reverification, so its oracle never reaches the approval loop and `--approve` cannot record consent for it. The run said nothing and printed `ALL MET`, which reads as approval granted, while the next reverification stopped on the same requirement the run appeared to satisfy. The pending-approval hint now names `--reverify --approve`, the form that actually reaches the oracle; naming the bare flag sent the reader around a loop whose middle step reported success and changed nothing. Reverifying against a worktree meets this on every leaf, because the resolved working directory is a bound input.
- Derive the reported met count from what the gates did rather than from the size of the map collecting extra unmet items. That subtraction is correct only for entries that are themselves gates already counted as met; an ownership breach and an unreadable plan are entries in the same map and were never gates, so each finding silently took one passing gate off the count. Three passing gates beside one ownership breach reported `met: 2`, and a single passing gate beside one reported `met: 0`. That count is the figure the skill instructs the agent to publish.
- Say `git was not found on PATH` instead of relaying `spawnSync git ENOENT`. The runtime's description of its own call reads as a defect in unlazy rather than a missing program, and this line is the one a reader has to act on.
- State that concurrent dispatch needs a git repository. The audit is the whole basis for verifying a registered leaf, so without history every one of them stays unverified for a reason no document named, and a permanent refusal reads as a fault in the leaf's work. A project that keeps no version control can initialise a repository, or register nothing and work leaves one at a time against solo ledgers.
- State identity exclusivity outright instead of relying on it emerging. A repeated claim used to be refused only because it overlapped its own held globs, so a pathless registration, having no globs, would have silently re-registered and let two workers sharing one logical identity both believe they owned it.

- Add scoped pipelines under `.unlazy/<scope>/`, qualified gate ids, session binding, append-only status logging, and explicit scope discovery refusal when the target is ambiguous.
- Add repository-relative `OWNS:` declarations with `--claim` and `--release`. Serialize claim discovery and creation under one lock, reject unsafe paths, and use conservative overlap detection.
- Treat a scope/leaf identity as an exclusive lease owner so duplicate workers cannot both claim and later release the same logical lease.
- Describe scopes and leases as coordination rather than filesystem or process isolation.
- Add opt-in `--jobs <N>` rolling check concurrency while retaining sequential default behavior and deterministic ledger-order reporting.
- Add declared readiness states, real `node-*` branch paths, explicit dependencies, and rolling leaf dispatch to the plan and orchestration guide.
- Add atomic native dispatch waves that require every independent leaf to receive a distinct host start handle before the first return is accepted.
- Add auditable dispatch abandonment for irrecoverable partial launches. Preserve the reason and timestamps in state, make status non-successful, and keep abandoned waves visible without permanently blocking Stop.
- Make scoped `gate-check` the aggregate completion oracle for both ledgers and dispatch waves; per-wave status and the optional Stop hook are no longer required to prevent a false completion certificate.
- Add Codex and Claude Code launch adapters, incomplete-wave Stop-hook enforcement, and a measured worker-overlap regression without adding a model subprocess runner.
- Key Stop-hook progress state to the session and scope, serialize state changes, and retain unlazy's own six-block no-progress release.
- Compare resolved gate state between stops rather than raw ledger bytes. A comment, a reflowed line, or a rewritten evidence line no longer counts as progress, so the six-block release can fire for an agent that is editing without advancing.
- Compare canonical dispatch state and counts in the same guard, so timestamps and metadata do not impersonate launch progress.
- Say which layout the `--status` and `--approve` examples belong to. They name a solo ledger at the repository root, which does not exist once a scoped pipeline is in use, so the first command a parallel-mode reader was handed failed immediately with `no such gate file`.
- Require a worktree per concurrently dispatched leaf that writes tracked files, and say why a lease cannot substitute: disjoint `OWNS:` paths still share one index, so a leaf that stages broadly commits a sibling's work under its own contract. Route setup to the host's native worktree facility before a manual `git worktree add`.
- State what a worktree does and does not isolate. A linked worktree owns its working directory, `HEAD`, and index, so separate worktrees on separate branches do not contend for one index lock. It shares the object database, the ref store, and `.git/config`. Caches, ports, and external services stay shared.
- Describe the shared-config failure as silent rather than loud. One shared config holds one value per key, so the last writer wins and every worktree reads that value, including worktrees that never wrote it and the main checkout. A failure to take the config lock also happens but is intermittent, so an agent waiting for `could not lock config file` before changing approach usually gets silently wrong values instead. Give each leaf its commit identity through `--worktree` config scope, which neither contends nor leaks.
- Recommend absolute paths once verification leaves the driver's root. A relative `--cwd` and a relative ledger path both resolve against `--root` rather than the invocation directory, so relative forms that look correct compose into paths that do not exist.
- Add a durability ordering to the dispatch contract. A scheduler return does not prove a leaf's work survived, so the workspace and lease must outlive the return until parent reverification passes. Removing a worktree at return time destroys any leaf that returned without committing, and the wave records both cases identically.
- Make the git fallback runnable rather than named in passing. Show the create and remove commands with branch and placement, and test the ignore rule with a trailing slash: a directory-only rule such as `.worktrees/` does not match the path `.worktrees` until that directory exists, so the unslashed form reports a wrong "not ignored" in exactly the pre-creation state the check runs in.
- Qualify the native-worktree-facility preference. A launch-tool isolation option is commonly scoped to the driver's own repository rather than the repository the dispatched work lives in, and a tool schema rarely states which. Isolating the wrong tree looks like success while leaving every leaf in one shared checkout, so establish the target or use the git fallback.
- Show how to reverify one leaf that ran in its own worktree. `--leaf` selects a lease rather than a ledger, and without an explicit `--cwd` the check resolves against the driver's `.unlazy/<scope>/gates` directory instead of the worktree holding the work. Record that an unapproved oracle prints `NOT RUN`, which has measured nothing, so tearing down after one destroys unverified work exactly as a premature return would.
